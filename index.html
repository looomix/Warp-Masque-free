HOW
工作原理

        

          
01
Actions 注册设备
工作流在 GitHub Runner 中运行 usque 完成 WARP/MASQUE 设备注册，密钥只在 Runner 与产物中短暂存在。

          
02
测速 + 生成
scripts/generate.py 批量探测端点、按延迟排序并剔除不可达端口，再输出 YAML / .conf / sing-box / 分享链接。

          
03
静态站点托管
YAML 与快照提交到仓库，由 GitHub Pages 与 gh-proxy 镜像提供订阅；页面只做读取、预览与回滚引导。

        

      


      

        
FAQ
常见问题

        

          
为什么用 GitHub Actions？
Cloudflare 注册接口不允许浏览器跨域调用，而 GitHub Actions 的 Runner 是服务端环境，可以直接运行 usque 完成注册。生成的 YAML 提交回仓库后，GitHub Pages 就能作为公开订阅源，不需要 Cloudflare Worker。

          
点了“一键清空”后，为什么重新打开还会出现？
旧版本只清空了当前页面，刷新后仍会自动拉取 configs/usque-config.json 回填。现在清空后会写入浏览器本地标记（localStorage），下次打开保持空白；只有点击“刷新订阅内容”或“恢复订阅地址”才会重新载入。

          
测速是怎么做的？
Runner 对官方端点 × 端口并发探测：443 / 8443 做 TCP + TLS 握手（带 SNI），其余做 TCP 连接，测出延迟后排序，超过阈值的端点不写入订阅。它反映的是端点可达性，最终体验还取决于你本地网络。

          
为什么有时没有 WireGuard .conf / sing-box？
这两个格式需要 32 字节 X25519 私钥，而 usque 注册的 MASQUE 账号用的是 EC P-256 密钥，无法直接转换。用 wgcf 注册的 WARP 账号粘贴进来即可导出 .conf 与 sing-box 配置。

          
AWG 档位会改变 WARP 服务端吗？
不会。Cloudflare 始终是标准 WireGuard peer；AWG 1.5/2.0/3.x 参数只写在客户端配置的 Interface 段，用于握手伪装与填充。

          
订阅链接格式？
Actions 生成的订阅地址会随仓库自动确定。
